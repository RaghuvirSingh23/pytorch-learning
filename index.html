A Deep Dive PyTorch, from first principles.

You built a GPT out of plain Python numbers: a Value class, hand-written backward(), and Adam in a for loop. It works and it's slow. PyTorch is the same ideas, done for whole grids of numbers at once, with the gradient bookkeeping done for you. This tutorial starts at "what is a tensor" and ends with you rebuilding microgpt in PyTorch: batched training, a KV cache, sampling, and a profile that shows where the time goes.

14 chapters 90+ exercises 50 interview-style questions ~8 hours to read, weeks to internalise

How to use this tutorial

This is a hands-on tutorial. You learn PyTorch by running it and looking at what comes back: shapes, numbers, gradients. Every chapter contains:

  • Concept prose: what the feature is, why it exists, and the smallest example that shows it.
  • Code examples: every snippet is copy-pasteable and was run against PyTorch 2.8. Expected output is shown in comments or in an output block.
  • Hands-on blocks: things you should actually type, with what you should see.
  • microgpt links: where the idea shows up in microgpt.py, so each new API lands on code you already understand.
  • Pitfalls: the bugs that cost real people real days.
  • Exercises: several per chapter, each with a collapsible solution. Do them. Don't peek.
Before you start

Make a scratch directory with its own virtual environment and stay in it for the whole course:

$ mkdir -p ~/learning-pytorch && cd ~/learning-pytorch
$ python3 -m venv .venv && source .venv/bin/activate
$ pip install torch numpy
$ python -c "import torch; print(torch.__version__)"
2.8.0

Any PyTorch 2.x prints a version and works for almost everything here. Chapters that need a GPU say so, and show what to expect on CPU or Apple Silicon (mps) instead.

What you will learn

By the end of this tutorial you will:

  • Read any tensor expression and say its output shape before you run it, including broadcasting and batched matmul.
  • Explain what loss.backward() does in terms of the Value engine you already wrote, and know when gradients accumulate, when they're freed, and how to turn tracking off.
  • Write nn.Modules for embeddings, attention, RMSNorm, and MLPs, and know exactly which tensors are parameters, buffers, or plain intermediates.
  • Write a training loop that is correct (zero grads, train/eval modes, checkpoints) and fast enough (batches, devices, mixed precision).
  • Run inference the way serving engines do: inference_mode, temperature, top-k/top-p, and a KV cache in PyTorch.
  • Time GPU code correctly, read a profiler trace, and debug shape errors, NaNs, and silent broadcasting bugs.

Prerequisites

  • Comfortable Python: functions, classes, list comprehensions.
  • The transformer at the level of microgpt.py: embeddings, attention, MLP, softmax, cross-entropy, and Adam. If you can explain what gpt_step does, you're ready.
  • High-school calculus is enough: "the derivative says which way is downhill". Chapter 4 rebuilds the rest.
  • A GPU is optional. Everything runs on a laptop CPU; the GPU-only parts (CUDA timing, TF32, GradScaler) say so.
What this tutorial is not

This is not a reference manual. For exhaustive detail, read the official PyTorch documentation and the official tutorials. This tutorial is the curriculum those docs assume you already have: a guided path through the parts you will actually use to train and serve language models, with exercises that build the intuition a reference page can't.
