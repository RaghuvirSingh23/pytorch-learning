Chapter 05 nn.Module

nn.Module is the class every PyTorch model inherits from. Strip away the features and it is a registry: it knows which tensors are trainable parameters, which are fixed buffers, and which other modules it contains, so that optimizers, .to(device) and checkpoints can find all of them. This chapter builds that picture from microgpt's hand-made parameter list up to state_dict and train/eval mode.

Why modules exist

In microgpt_scalar.py you kept track of your weights by hand. Every matrix had to be listed once more at the bottom, then flattened, so Adam could loop over them:

pythonmicrogpt_scalar.py (excerpt)
parameter_matrices = [
    token_embedding_table,
    position_embedding_table,
    query_weights,
    ...
    language_model_head_weights,
]

parameters = [
    parameter
    for matrix in parameter_matrices
    for row in matrix
    for parameter in row
]

assert len(parameters) == 4192

Forget one matrix in that list and it silently never trains. nn.Module removes the list: any nn.Parameter you assign as an attribute in __init__ is recorded automatically, and model.parameters() yields all of them. That's why microgpt.py can write torch.optim.Adam(model.parameters(), ...).

An nn.Parameter is a tensor subclass with two differences: it has requires_grad=True by default, and assigning it to a module attribute registers it. A plain tensor, even one with requires_grad=True, is just an attribute:

import torch
from torch import nn

class Demo(nn.Module):
    def __init__(self):
        super().__init__()
        self.w = nn.Parameter(torch.zeros(2, 3))              # registered
        self.t = torch.zeros(2, 3, requires_grad=True)        # just an attribute

m = Demo()
print([name for name, _ in m.named_parameters()])
print(type(m.w).__name__, m.w.requires_grad, m.w.is_leaf)
print(list(m._parameters.keys()), "t" in m.__dict__)
['w']
Parameter True True
['w'] True

The optimizer would never see t. It wouldn't be saved in a checkpoint or moved to the GPU either.

Under the hood: __setattr__

nn.Module overrides __setattr__. When you write self.w = value, it checks the type of value: an nn.Parameter goes into the dict self._parameters, an nn.Module into self._modules, and anything else into the ordinary instance __dict__. parameters() walks _parameters and then recurses into _modules. That is also why super().__init__() must come first: it creates those dicts. Assign a parameter before calling it and you get AttributeError: cannot assign parameters before Module.__init__() call.

__init__ and forward

A module has two parts. __init__ creates the state (parameters, buffers, submodules). forward says what to compute from an input. You never write a backward: autograd records whatever forward does.

class Scale(nn.Module):
    def __init__(self):
        super().__init__()
        self.g = nn.Parameter(torch.tensor(2.0))

    def forward(self, x):
        return x * self.g

s = Scale()
s.register_forward_hook(lambda module, inputs, output: print("hook saw", tuple(output.shape)))

x = torch.ones(3)
y1 = s(x)            # nn.Module.__call__: pre-hooks, forward, hooks
y2 = s.forward(x)    # forward only: the hook is skipped
print(y1, torch.equal(y1, y2))
hook saw (3,)
tensor([2., 2., 2.], grad_fn=<MulBackward0>) True

Always call the module, model(x), never model.forward(x). Calling goes through nn.Module.__call__, which runs any registered hooks (functions that observe or modify a module's inputs and outputs) around forward. Profilers, activation-capture tools, quantization and some distributed wrappers rely on hooks; calling forward directly bypasses all of them, as the single "hook saw" line shows. microgpt does it right: logits = model(input_ids).

Counting parameters: 4,192 again

FastMicroGPT in microgpt.py creates nine matrices with a helper make_parameter(rows, cols), which builds the values and wraps them in nn.Parameter. Here is a module with exactly the same names and shapes (and torch.randn * 0.08 instead of random.gauss, for brevity):

pythoncount_params.py
import torch
from torch import nn

class MicroGPTParams(nn.Module):
    """Same parameter shapes as FastMicroGPT in microgpt.py."""
    def __init__(self, vocab_size=27, n_embd=16, block_size=16):
        super().__init__()

        def make_parameter(rows, cols):
            return nn.Parameter(torch.randn(rows, cols) * 0.08)

        C = n_embd
        self.token_embedding_table = make_parameter(vocab_size, C)
        self.position_embedding_table = make_parameter(block_size, C)
        self.query_weights = make_parameter(C, C)
        self.key_weights = make_parameter(C, C)
        self.value_weights = make_parameter(C, C)
        self.attention_output_weights = make_parameter(C, C)
        self.mlp_expand_weights = make_parameter(4 * C, C)
        self.mlp_contract_weights = make_parameter(C, 4 * C)
        self.language_model_head_weights = make_parameter(vocab_size, C)

torch.manual_seed(0)
model = MicroGPTParams()

named_parameters() yields (name, tensor) pairs; parameters() yields just the tensors; p.numel() is the number of elements. sum(p.numel() for p in model.parameters()) is the one-liner every codebase uses, and the exact assert in microgpt.py.

Note the leaf

nn.Parameter(torch.randn(r, c) * 0.08) is safe: the multiply happens on a tensor that doesn't require grad, then Parameter wraps the result as a fresh leaf. Compare EX 4.4, where torch.randn(..., requires_grad=True) * 0.08 produced a non-leaf and lost its gradient.

Buffers: state that isn't trained

Some tensors belong to the model but must not be trained: a causal mask, BatchNorm's running averages, a RoPE frequency table. Register them as buffers with register_buffer(name, tensor). FastMicroGPT does this for its mask:

class MaskDemo(nn.Module):
    def __init__(self, block_size=4):
        super().__init__()
        self.w = nn.Parameter(torch.randn(3, 3))
        causal_mask = torch.triu(torch.ones(block_size, block_size, dtype=torch.bool), diagonal=1)
        self.register_buffer("causal_mask", causal_mask, persistent=False)
        self.register_buffer("step_count", torch.zeros((), dtype=torch.long))  # persistent

m = MaskDemo()
print([n for n, _ in m.named_parameters()])
print([n for n, _ in m.named_buffers()])
print(list(m.state_dict().keys()))
print(m.causal_mask)
['w']
['causal_mask', 'step_count']
['w', 'step_count']
tensor([[False,  True,  True,  True],
        [False, False,  True,  True],
        [False, False, False,  True],
        [False, False, False, False]])

A buffer is not in parameters(), so the optimizer never updates it. By default it is saved in state_dict (the checkpoint dictionary covered below). persistent=False leaves it out, which is right for the causal mask: it is cheap to rebuild from block_size, so storing it in every checkpoint is waste.

Buffers do follow the module through .to(). That's the reason to register a mask instead of keeping a plain attribute: the forward pass needs the mask on the same device as the activations.

class MaskDemo(nn.Module):
    def __init__(self, block_size=4):
        super().__init__()
        self.w = nn.Parameter(torch.randn(3, 3))
        causal_mask = torch.triu(torch.ones(block_size, block_size, dtype=torch.bool), diagonal=1)
        self.register_buffer("causal_mask", causal_mask, persistent=False)
        self.plain = torch.ones(2)          # not registered

m = MaskDemo()
m = m.to(torch.float64)
print(m.w.dtype, m.causal_mask.dtype, m.plain.dtype)

device = "mps" if torch.backends.mps.is_available() else "cpu"
m = m.to(torch.float32).to(device)
print(m.w.device, m.causal_mask.device, m.plain.device)
torch.float64 torch.bool torch.float32
mps:0 mps:0 cpu

Two details. A dtype cast like .to(torch.float64) only converts floating-point tensors, so the boolean mask stays boolean. And the unregistered plain tensor stayed behind on the CPU. (This ran on an Apple Silicon Mac, so the device is mps:0; on an NVIDIA machine use "cuda" and you'd see cuda:0. MPS has no float64, hence the cast back to float32 first.)

Submodules and containers

Assign a module as an attribute of another module and it becomes a submodule. Parameters are then found recursively, with dotted names:

class MLP(nn.Module):
    def __init__(self, C=16):
        super().__init__()
        self.expand = nn.Linear(C, 4 * C, bias=False)
        self.contract = nn.Linear(4 * C, C, bias=False)

    def forward(self, x):
        return self.contract(torch.relu(self.expand(x)))

class TwoBlocks(nn.Module):
    def __init__(self):
        super().__init__()
        self.first = MLP()
        self.second = MLP()

    def forward(self, x):
        return self.second(self.first(x))

net = TwoBlocks()
for name, p in net.named_parameters():
    print(name, tuple(p.shape))
print([name for name, _ in net.named_children()])
print(sum(1 for _ in net.modules()))
first.expand.weight (64, 16)
first.contract.weight (16, 64)
second.expand.weight (64, 16)
second.contract.weight (16, 64)
['first', 'second']
7

named_children() gives direct submodules only; modules() walks the whole tree including the root (here 1 + 2 + 4 = 7). The MLP class is microgpt's mlp() without the norm: linear, relu, linear.

  • nn.Sequential has a forward: it feeds each module's output to the next. Use it for straight pipelines. nn.ReLU() is a module with no parameters, which is why the names jump from 0 to 2.
  • nn.ModuleList has no forward. It is a list that registers its contents. Use it for "N transformer blocks" where you write the loop yourself.
  • nn.ModuleDict is the same, keyed by string. Use it when modules are chosen by name.
The plain-list bug: parameters disappear

A Python list is not a module, so __setattr__ files it under ordinary attributes and never looks inside:

class Broken(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = [nn.Linear(16, 16) for _ in range(3)]    # plain Python list

    def forward(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

class Fixed(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.ModuleList([nn.Linear(16, 16) for _ in range(3)])

    def forward(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

for cls in (Broken, Fixed):
    m = cls()
    n = sum(p.numel() for p in m.parameters())
    print(f"{cls.__name__:6s} params={n:4d} state_dict keys={len(m.state_dict())}")

torch.optim.Adam(Broken().parameters(), lr=0.01)
Broken params=   0 state_dict keys=0
Fixed  params= 816 state_dict keys=6
ValueError: optimizer got an empty parameter list

Broken still runs forward perfectly. If it has some registered parameters elsewhere, the optimizer error never fires and the layers in the list just never train, never get saved, and stay on the CPU when you call .to("cuda"). Same trap with a plain dict: use nn.ModuleDict.

nn.Linear and nn.Embedding from the inside

nn.Linear

nn.Linear(in_features, out_features) holds a weight of shape [out, in] and a bias of shape [out], and computes y = x @ weight.T + bias. That is the same [out][in] layout as your make_matrix weights, and the same math as your linear(): one dot product per output row, but for a whole batch of input vectors at once.

import math
import torch.nn.functional as F

torch.manual_seed(0)
lin = nn.Linear(16, 64)                 # in_features=16, out_features=64
print(lin.weight.shape, lin.bias.shape)

x = torch.randn(5, 16)                  # 5 vectors of size 16
y = lin(x)
print(y.shape)
print(torch.allclose(y, x @ lin.weight.T + lin.bias))
print(torch.allclose(y, F.linear(x, lin.weight, lin.bias)))

bound = 1 / math.sqrt(16)
print(round(bound, 4), lin.weight.abs().max().item() <= bound, lin.bias.abs().max().item() <= bound)
torch.Size([64, 16]) torch.Size([64])
torch.Size([5, 64])
True
True
0.25 True True

F.linear(x, W, b) is the stateless function underneath; FastMicroGPT calls it directly with its own nn.Parameter matrices (F.linear(normalized_inputs, self.query_weights)). The default initialisation is uniform in [-1/√in, 1/√in] for both weight and bias (implemented as kaiming_uniform_(a=√5) in reset_parameters()). With in = 16 the bound is 0.25. Transformers usually disable the bias (bias=False), as microgpt does.

nn.Embedding

nn.Embedding(num_embeddings, embedding_dim) is a lookup table: one Parameter of shape [num, dim], and the forward pass is row indexing. Nothing more.

torch.manual_seed(0)
emb = nn.Embedding(27, 16)              # 27 tokens, 16 numbers each
print(emb.weight.shape, type(emb.weight).__name__)

ids = torch.tensor([26, 0, 13])         # BOS, 'a', 'n'
out = emb(ids)
print(out.shape, torch.equal(out, emb.weight[ids]))
print(round(emb.weight.std().item(), 3))
torch.Size([27, 16]) Parameter
torch.Size([3, 16]) True
0.994

So FastMicroGPT's self.token_embedding_table[token_ids] is exactly nn.Embedding's forward. The gradient of a lookup only touches the rows that were used. Default init is a standard normal (std 1), much larger than microgpt's 0.08.

Custom initialisation with apply

torch.nn.init has in-place initialisers (normal_, zeros_, uniform_, xavier_uniform_, ...). They run under no_grad internally, so they are safe on parameters. model.apply(fn) calls fn on every submodule (children first, then the module itself), which is the usual way to re-initialise a whole model:

def init_like_microgpt(module):
    if isinstance(module, (nn.Linear, nn.Embedding)):
        nn.init.normal_(module.weight, mean=0.0, std=0.08)
    if isinstance(module, nn.Linear) and module.bias is not None:
        nn.init.zeros_(module.bias)

torch.manual_seed(0)
net = nn.Sequential(nn.Embedding(27, 16), nn.Linear(16, 64), nn.ReLU(), nn.Linear(64, 16))
net.apply(init_like_microgpt)

for name, p in net.named_parameters():
    print(f"{name:9s} std={p.std().item():.4f} max|p|={p.abs().max().item():.4f}")

state_dict and load_state_dict

model.state_dict() returns an ordered dictionary from dotted name to tensor, for every parameter and persistent buffer. It is what you save. model.load_state_dict(sd) copies those values into an existing model with the same structure.

class Tiny(nn.Module):
    def __init__(self):
        super().__init__()
        self.embed = nn.Embedding(27, 16)
        self.head = nn.Linear(16, 27, bias=False)
        self.register_buffer("causal_mask", torch.ones(4, 4, dtype=torch.bool), persistent=False)

torch.manual_seed(0)
a = Tiny()
sd = a.state_dict()
for k, v in sd.items():
    print(k, tuple(v.shape), v.requires_grad)

b = Tiny()                                  # different random weights
print(torch.equal(a.head.weight, b.head.weight))
result = b.load_state_dict(sd)              # copies values in place
print(result)
print(torch.equal(a.head.weight, b.head.weight))
print(sd["head.weight"].data_ptr() == a.head.weight.data_ptr())
embed.weight (27, 16) False
head.weight (27, 16) False
False
<All keys matched successfully>
True
True

The values in a state_dict are detached (requires_grad=False) but share memory with the live parameters (the last line). Saving to disk is fine, but if you keep a state_dict in memory as a "best model" snapshot, training will keep changing it. Use copy.deepcopy(model.state_dict()) for a real snapshot.

strict loading, missing and unexpected keys

By default load_state_dict is strict=True: the key sets must match exactly. Rename an attribute and old checkpoints stop loading:

class Old(nn.Module):
    def __init__(self):
        super().__init__()
        self.query_weights = nn.Parameter(torch.zeros(16, 16))
        self.lm_head = nn.Linear(16, 27, bias=False)

class New(nn.Module):
    def __init__(self):
        super().__init__()
        self.q = nn.Linear(16, 16, bias=False)
        self.lm_head = nn.Linear(16, 27, bias=False)

sd = Old().state_dict()
new = New()
new.load_state_dict(sd)
RuntimeError: Error(s) in loading state_dict for New:
	Missing key(s) in state_dict: "q.weight".
	Unexpected key(s) in state_dict: "query_weights".

Missing keys are in the model but not the file; unexpected keys are in the file but not the model. load_state_dict(sd, strict=False) loads whatever matches and returns the lists instead of raising: _IncompatibleKeys(missing_keys=['q.weight'], unexpected_keys=['query_weights']). Always print and check that result; a silent strict=False is how a model ends up running with half its weights at random init. Shapes are checked even with strict=False: a mismatch raises size mismatch for weight: copying a param with shape torch.Size([27, 16]) from checkpoint, the shape in current model is torch.Size([28, 16]).

torch.load and weights_only

Since PyTorch 2.6, torch.load defaults to weights_only=True: it only unpickles tensors and plain containers (dicts, lists, tuples, strings, numbers), because unpickling arbitrary objects can run arbitrary code. microgpt passes weights_only=False, but its checkpoint only contains allowed types and loads fine with the safe default. Only pass False for files you trust.

train() and eval()

Every module has a boolean training attribute. model.train() sets it to True on the module and every submodule; model.eval() sets it to False. A few layers read that flag and behave differently:

  • Dropout zeroes a random fraction p of values in training (and scales the rest by 1/(1-p) so the expected value is unchanged). In eval it does nothing.
  • BatchNorm normalises with the current batch's statistics and updates its running-average buffers in training. In eval it uses the stored running averages and leaves them alone.
torch.manual_seed(0)
net = nn.Sequential(nn.Linear(4, 4), nn.Dropout(p=0.5))
x = torch.ones(1, 4)

print(net.training, net[1].training)        # modules start in training mode
print(net(x))
print(net(x))                               # different: dropout is random

net.eval()                                  # sets .training = False on every submodule
print(net.training, net[1].training)
print(net(x))
print(net(x))                               # identical: dropout is a no-op now

y = net(x)
print(y.requires_grad, y.grad_fn is not None)   # eval() did NOT turn off autograd
True True
tensor([[-0.6347,  1.2561, -1.0009, -0.0000]], grad_fn=<MulBackward0>)
tensor([[-0.6347,  1.2561, -1.0009, -2.4283]], grad_fn=<MulBackward0>)
False False
tensor([[-0.3173,  0.6281, -0.5004, -1.2141]], grad_fn=<AddmmBackward0>)

The training-mode values are the eval values times 2 (that's the 1/(1-p)), with random entries zeroed. The last line is the point most people get wrong: eval() does not turn off gradients. It changes layer behaviour; autograd still records everything. For inference you need both, which is exactly what microgpt.py does: evaluate_model is decorated with @torch.inference_mode() and starts with model.eval(). The training loop calls model.train() before it starts.

microgpt has no dropout or BatchNorm, so its outputs don't change between modes. The calls are still correct habit: the day you add a dropout layer, the code is already right.

EX 5.1 easy Count parameters in your head

Predict sum(p.numel() for p in m.parameters()) for each, then check: nn.Linear(16, 64), nn.Linear(16, 64, bias=False), nn.Embedding(27, 16), nn.RMSNorm(16), nn.RMSNorm(16, elementwise_affine=False), nn.LayerNorm(16).

Show solution 
from torch import nn

def count(m):
    return sum(p.numel() for p in m.parameters())

print(count(nn.Linear(16, 64)))                            # 1088 = 64*16 + 64
print(count(nn.Linear(16, 64, bias=False)))                # 1024
print(count(nn.Embedding(27, 16)))                         # 432
print(count(nn.RMSNorm(16)))                               # 16: one gain per feature
print(count(nn.RMSNorm(16, elementwise_affine=False)))     # 0
print(count(nn.LayerNorm(16)))                             # 32: gain + bias

microgpt's rms_norm has no learnable gain, so it matches elementwise_affine=False. That is one reason its total is exactly 4,192.

EX 5.2 easy Parameter, buffer, or neither?

Classify each, and say whether a buffer should be persistent: (a) the causal mask; (b) the position embedding table; (c) BatchNorm's running mean; (d) a precomputed RoPE cos/sin table; (e) a KV cache filled during generation; (f) RMSNorm's gain.

Show solution
  • (a) Buffer, persistent=False: fixed, derivable from block_size, must move with the model.
  • (b) Parameter: it is learned. (In microgpt it is position_embedding_table.)
  • (c) Buffer, persistent: not trained by gradients, but it is learned state you need at eval time. nn.BatchNorm1d(2) has parameters ['weight', 'bias'] and buffers ['running_mean', 'running_var', 'num_batches_tracked'].
  • (d) Buffer, persistent=False: a pure function of the config, like the mask.
  • (e) Usually neither: per-request state that belongs to the generation loop, not the model. Some implementations do register it as a non-persistent buffer so it follows .to(); it must never be in a checkpoint.
  • (f) Parameter (when elementwise_affine=True).
EX 5.3 medium Find and fix the plain-list bug

A colleague's model trains but the loss plateaus early. Its __init__ contains self.blocks = [Block() for _ in range(4)] next to a properly registered embedding and head. List three symptoms you could check for in one minute, then fix it. Bonus: show what .to(device) does to the listed layers.

Show solution

Symptoms: (1) the parameter count is far lower than expected; (2) state_dict() has no blocks.* keys; (3) after optimizer.step(), the block weights are unchanged (or their .grad is non-None but they still never move, since the optimizer doesn't hold them). The forward pass works, which is why it went unnoticed. Fix: self.blocks = nn.ModuleList([Block() for _ in range(4)]).

class Broken(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = [nn.Linear(16, 16) for _ in range(3)]

device = "mps" if torch.backends.mps.is_available() else "cpu"
m = Broken().to(device)
print(m.layers[0].weight.device)          # cpu: .to() never saw it

If the registered embedding feeds those layers, the first forward pass on the accelerator fails with a device-mismatch error, which is more helpful than a silent plateau. On this Mac it read RuntimeError: Tensor for argument weight is on cpu but expected on mps; on a CUDA GPU the message starts with Expected all tensors to be on the same device.

EX 5.4 medium Load a checkpoint after renaming

You refactored a flat model (keys query_weights, key_weights, like FastMicroGPT) into one with an attn submodule holding q and k as nn.Linear(16, 16, bias=False). Load the old weights into the new model with strict=True and prove the values arrived.

Show solution

Because microgpt stores weights as [out][in], the same layout as nn.Linear.weight, only the names change. No transpose needed.

class Attention(nn.Module):
    def __init__(self, C=16):
        super().__init__()
        self.q = nn.Linear(C, C, bias=False)
        self.k = nn.Linear(C, C, bias=False)

class Model(nn.Module):
    def __init__(self):
        super().__init__()
        self.attn = Attention()

torch.manual_seed(0)
old_sd = {"query_weights": torch.randn(16, 16), "key_weights": torch.randn(16, 16)}

rename = {"query_weights": "attn.q.weight", "key_weights": "attn.k.weight"}
new_sd = {rename.get(k, k): v for k, v in old_sd.items()}

model = Model()
print(model.load_state_dict(new_sd))                               # <All keys matched successfully>
print(torch.equal(model.attn.q.weight, old_sd["query_weights"]))   # True

Keep strict=True and remap the keys. It guarantees every weight landed somewhere. This is exactly what Hugging Face conversion scripts do when they port a checkpoint between codebases.

EX 5.5 medium Freeze the embeddings

Build a model with token embedding (27, 16), position embedding (16, 16), an MLP 16 → 64 → 16 without biases and a head 16 → 27 without bias. Freeze both embeddings. Print the total and trainable parameter counts, and build an Adam optimizer that only receives trainable parameters.

Show solution 
class Tiny(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok = nn.Embedding(27, 16)
        self.pos = nn.Embedding(16, 16)
        self.mlp = nn.Sequential(nn.Linear(16, 64, bias=False), nn.ReLU(), nn.Linear(64, 16, bias=False))
        self.head = nn.Linear(16, 27, bias=False)

model = Tiny()
for p in list(model.tok.parameters()) + list(model.pos.parameters()):
    p.requires_grad_(False)

total = sum(p.numel() for p in model.parameters())
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(total, trainable)                                   # 3168 2480

opt = torch.optim.Adam([p for p in model.parameters() if p.requires_grad], lr=0.01)
print(sum(p.numel() for g in opt.param_groups for p in g["params"]))   # 2480

Frozen parameters still appear in parameters() and state_dict(); only requires_grad changed. Passing them to the optimizer anyway is harmless here (their .grad stays None, so Adam skips them), but filtering makes the intent explicit and avoids allocating optimizer state for them.

EX 5.6 hard Write your own module registry

Without inheriting from nn.Module, write a TinyModule base class whose __setattr__ registers nn.Parameters and child TinyModules, with named_parameters() producing dotted names recursively and __call__ calling forward. Build TinyLinear and a TinyMLP (16 → 64 → 16) on it and check that a plain tensor attribute is not registered.

Show solution 
import torch
from torch import nn

class TinyModule:
    def __init__(self):
        object.__setattr__(self, "_params", {})
        object.__setattr__(self, "_modules", {})

    def __setattr__(self, name, value):
        if isinstance(value, nn.Parameter):
            self._params[name] = value
        elif isinstance(value, TinyModule):
            self._modules[name] = value
        object.__setattr__(self, name, value)

    def named_parameters(self, prefix=""):
        for name, p in self._params.items():
            yield prefix + name, p
        for name, child in self._modules.items():
            yield from child.named_parameters(prefix + name + ".")

    def parameters(self):
        for _, p in self.named_parameters():
            yield p

    def __call__(self, *args):
        return self.forward(*args)

class TinyLinear(TinyModule):
    def __init__(self, n_in, n_out):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(n_out, n_in) * 0.08)

    def forward(self, x):
        return x @ self.weight.T

class TinyMLP(TinyModule):
    def __init__(self, C):
        super().__init__()
        self.expand = TinyLinear(C, 4 * C)
        self.contract = TinyLinear(4 * C, C)
        self.scratch = torch.zeros(C)          # plain tensor: not registered

    def forward(self, x):
        return self.contract(torch.relu(self.expand(x)))

torch.manual_seed(0)
mlp = TinyMLP(16)
print([(n, tuple(p.shape)) for n, p in mlp.named_parameters()])
print(sum(p.numel() for p in mlp.parameters()))
print(mlp(torch.randn(3, 16)).shape)
[('expand.weight', (64, 16)), ('contract.weight', (16, 64))]
2048
torch.Size([3, 16])

object.__setattr__ in __init__ avoids recursion: our own __setattr__ needs _params to exist already. The real nn.Module does the same thing, plus buffers, hooks, state_dict, .to() (a recursive _apply over parameters and buffers) and train()/eval() (a recursive walk setting training).

EX 5.7 hard Resume training exactly

Prove that a checkpoint with both model_state_dict and optimizer_state_dict (microgpt's layout) resumes training bit-for-bit: run 3 Adam steps, save, run a 4th step; then load the checkpoint into fresh objects and run the same 4th step. Compare the parameters. Then repeat the resume without loading the optimizer state and measure the difference.

Show solution 
import torch
from torch import nn

def make_model():
    return nn.Sequential(nn.Linear(16, 64), nn.ReLU(), nn.Linear(64, 16))

def make_optimizer(model):
    return torch.optim.Adam(model.parameters(), lr=0.01, betas=(0.85, 0.99), eps=1e-8)

def train_step(model, optimizer, x):
    loss = model(x).pow(2).mean()
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

torch.manual_seed(0)
data = [torch.randn(8, 16) for _ in range(4)]

# Run A: 3 steps, checkpoint, 1 more step
model = make_model()
optimizer = make_optimizer(model)
for x in data[:3]:
    train_step(model, optimizer, x)
torch.save({"model_state_dict": model.state_dict(),
            "optimizer_state_dict": optimizer.state_dict(),
            "training_steps": 3}, "resume.pt")
train_step(model, optimizer, data[3])

# Run B: fresh objects, load the checkpoint, the same 1 step
model_b = make_model()
optimizer_b = make_optimizer(model_b)
ckpt = torch.load("resume.pt")
model_b.load_state_dict(ckpt["model_state_dict"])
optimizer_b.load_state_dict(ckpt["optimizer_state_dict"])
train_step(model_b, optimizer_b, data[3])

same = all(torch.equal(p, q) for p, q in zip(model.parameters(), model_b.parameters()))
print("resumed run identical:", same)

# Run C: forget the optimizer state
model_c = make_model()
optimizer_c = make_optimizer(model_c)
model_c.load_state_dict(ckpt["model_state_dict"])
train_step(model_c, optimizer_c, data[3])
diff = max((p - q).abs().max().item() for p, q in zip(model.parameters(), model_c.parameters()))
print(f"without optimizer state, max difference: {diff:.4f}")
resumed run identical: True
without optimizer state, max difference: 0.0175

Without the optimizer state, Adam restarts with zero moments and step = 1, so bias correction makes the first update roughly lr in size for every parameter: a visible jolt. Two more things must be restored for a truly identical long run: the learning-rate schedule position (microgpt recomputes it from training_iteration) and the random number generator state (torch.get_rng_state()), covered in Chapter 8.

Recap

  • nn.Module is a registry. Assigning an nn.Parameter or a submodule as an attribute registers it; plain tensors and plain lists are invisible.
  • Write __init__ (state) and forward (computation); call model(x) so hooks run.
  • sum(p.numel() for p in model.parameters()) counts parameters; microgpt's nine matrices give 4,192.
  • Buffers (register_buffer) move with .to() and are saved unless persistent=False, but are never trained. The causal mask is the textbook non-persistent buffer.
  • nn.Sequential chains, nn.ModuleList and nn.ModuleDict register collections. Never store modules in a Python list or dict.
  • nn.Linear: weight [out, in], y = x @ W.T + b, init uniform ±1/√in. nn.Embedding: weight[ids]. Re-initialise with torch.nn.init + model.apply.
  • state_dict maps names to tensors (sharing memory); load_state_dict is strict by default and reports missing and unexpected keys. Save the optimizer state too if you want to resume.
  • train()/eval() flip the training flag that dropout and BatchNorm read. They do not touch autograd: pair eval() with inference_mode().
