Chapter 06 Building a Transformer

FastMicroGPT.forward runs one name at a time: a (T, C) grid of activations. Real models run a batch of sequences, (B, T, C), so one kernel launch does B times the work. This chapter rebuilds microgpt as PyTorch modules that take batches, checking every piece against a reference as it goes, then assembles a GPT with microgpt's exact hyperparameters and 4,192 parameters.

From one sequence to a batch

Here is the core of FastMicroGPT.forward from microgpt.py, with shapes added. T is the sequence length, C = 16 the embedding size, H = 4 heads of D = 4 dimensions each.

pythonmicrogpt.py (excerpt, shapes added)
def forward(self, token_ids):                                   # (T,)
    sequence_length = token_ids.shape[0]
    inputs = (self.token_embedding_table[token_ids]
              + self.position_embedding_table[:sequence_length])  # (T, C)
    normalized_inputs = F.rms_norm(inputs, (fast_embedding_size,), eps=1e-5)
    query = F.linear(normalized_inputs, self.query_weights)       # (T, C)
    ...

                       fast_head_size).transpose(0, 1)            # (H, T, D)
    ...
    attention_logits = query @ key.transpose(-2, -1)              # (H, T, T)
    attention_logits = attention_logits / fast_head_size**0.5
    attention_logits = attention_logits.masked_fill(
        self.causal_mask[:sequence_length, :sequence_length], float("-inf"))

    concatenated_heads = attention_weights @ value                # (H, T, D)
    concatenated_heads = concatenated_heads.transpose(0, 1).reshape(
        sequence_length, fast_embedding_size)                     # (T, C)
    ...

Adding a leading batch dimension B changes surprisingly little, because most operations only touch the last dimension and treat everything in front of it as "a pile of vectors":

  • F.linear / nn.Linear, RMSNorm and softmax(dim=-1) work on any number of leading dimensions. (T, C) or (B, T, C), same code.
  • @ on tensors with more than two dimensions is a batched matmul: the last two dims are multiplied, the leading ones are batch dims.
  • Only the code that names dimensions by position must change: view(T, H, D).transpose(0, 1) becomes view(B, T, H, D).transpose(1, 2).

One idea is genuinely new compared with microgpt_scalar.py. Your gpt_step processed one token at a time and appended to a growing KV cache, so attention could never see the future: future keys didn't exist yet. Here all T positions are computed at once, and the causal mask is the only thing that stops position 2 from looking at position 3.

RMSNorm by hand vs nn.RMSNorm

Your rms_norm divides a vector by the square root of its mean square (plus a small eps so you never divide by zero). As a module, with the learnable per-feature gain most models add:

from torch.testing import assert_close

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))   # learnable gain, starts at 1

    def forward(self, x):
        mean_square = x.pow(2).mean(dim=-1, keepdim=True)     # (B, T, 1)
        return x * torch.rsqrt(mean_square + self.eps) * self.weight

torch.manual_seed(0)
x = torch.randn(2, 5, 16)
mine = RMSNorm(16, eps=1e-5)
theirs = nn.RMSNorm(16, eps=1e-5)
assert_close(mine(x), theirs(x))
print("match with eps=1e-5")

default = nn.RMSNorm(16)                       # eps=None: uses torch.finfo(x.dtype).eps
print(default.eps, torch.finfo(torch.float32).eps)
print((mine(x) - default(x)).abs().max().item())

  • keepdim=True keeps the reduced dimension as size 1, so (B, T, 1) broadcasts back against (B, T, C). Without it you'd get (B, T) and a shape error (or worse, a wrong broadcast).
  • torch.rsqrt is 1 / sqrt in one op; your (mean_square + 1e-5) ** -0.5.
  • nn.RMSNorm (added in PyTorch 2.4) defaults to eps=None, meaning machine epsilon for the dtype (about 1.2e-7 in float32), not microgpt's 1e-5. The outputs then differ by about 3e-5: small, but enough to fail assert_close and to make "my port doesn't match the reference" bugs. Always pass eps explicitly.
  • microgpt's norm has no gain, so use nn.RMSNorm(16, eps=1e-5, elementwise_affine=False): zero parameters, same as F.rms_norm(x, (16,), eps=1e-5). Your scalar test case gives the same numbers: nn.RMSNorm(2, eps=1e-5)(torch.tensor([[3.0, 4.0]])) prints tensor([[0.8485, 1.1314]], grad_fn=<MulBackward0>).

Q, K, V: three projections or one

Query, key and value are three Linear(C, C) layers applied to the same input. Three small matmuls are slower than one big one, so real implementations stack the three weight matrices into a single Linear(C, 3C) and split the output:

torch.manual_seed(0)
C = 16
x = torch.randn(2, 5, C)                     # (B, T, C), already normalised

q_proj = nn.Linear(C, C, bias=False)
k_proj = nn.Linear(C, C, bias=False)
v_proj = nn.Linear(C, C, bias=False)

qkv_proj = nn.Linear(C, 3 * C, bias=False)   # one matmul instead of three
with torch.no_grad():
    qkv_proj.weight.copy_(torch.cat([q_proj.weight, k_proj.weight, v_proj.weight], dim=0))

q, k, v = qkv_proj(x).split(C, dim=-1)       # three (B, T, C) views
print(qkv_proj.weight.shape, q.shape)
print(torch.allclose(q, q_proj(x)), torch.allclose(k, k_proj(x)), torch.allclose(v, v_proj(x)))
torch.Size([48, 16]) torch.Size([2, 5, 16])
True True True

Since weight is [out, in], stacking along dim=0 stacks output rows: rows 0–15 produce q, 16–31 produce k, 32–47 produce v. split(C, dim=-1) cuts the 48 outputs back into three chunks of 16. They are views, so the split itself copies nothing. The parameter count is identical (3 × 256 = 768).

Splitting heads

Your attention_head took head i as the slice query[i*D : (i+1)*D]. The tensor version reshapes the last dimension C into (H, D) and moves H in front of T, so heads become one more batch dimension:

Neither step moves data. view reinterprets the same memory with a new shape; transpose swaps two strides (Chapter 2). The result is not contiguous: walking along T now jumps 16 elements. That's fine for matmul, and it matters again when we merge the heads back.

Scores, causal mask, softmax, weighted sum

With q, k, v all (B, H, T, D), attention is four lines:

import math
import torch.nn.functional as F

torch.manual_seed(0)
B, H, T, D = 2, 4, 5, 4

scores = q @ k.transpose(-2, -1) / math.sqrt(D)     # (B, H, T, T)

  1. Scores. k.transpose(-2, -1) is (B, H, D, T), so q @ k^T is (B, H, T, T): row i, column j is the dot product of query i with key j. It is your attention_logits list, for every query at once. Dividing by √D keeps the scores' scale independent of head size, same as your / head_size**0.5.
  2. Mask. torch.triu(..., diagonal=1) is True strictly above the diagonal: column j > i, the future. masked_fill writes -inf wherever the mask is True.
  3. Softmax over the last dim. Each row (one query) becomes a probability distribution over keys. exp(-inf) = 0, so future positions get exactly zero weight. Row 0 can only see itself, so its weight is 1.
  4. Weighted sum. weights @ v: each query's output is the weighted average of value vectors, your head_output.
Softmax over the wrong dim, mask with the wrong diagonal

softmax(dim=-2) runs and gives the right shape, but normalises over queries instead of keys: columns sum to 1, rows don't. triu(diagonal=0) also masks the diagonal, so token 0 has nothing to attend to, its row is all -inf, and softmax returns nan. Check weights.sum(-1) is all ones and weights[0, 0, 0, 0] == 1 whenever you touch attention code.

Merging heads and the output projection

The per-head outputs (B, H, T, D) go back to (B, T, C): move H back next to D, then fuse them. This is your concatenated_head_outputs.extend(head_output).

out = out.transpose(1, 2)               # (B, T, H, D), not contiguous
out = out.contiguous().view(B, T, C)    # copy into row-major order, then fuse H*D = C
out = proj(out)                         # nn.Linear(C, C, bias=False): attention_output_weights

view only works when the requested shape can be expressed with strides over the existing memory. After the transpose, the four D-vectors of one token are 20 elements apart, so they can't be fused into one dimension of 16 without moving data. .contiguous() makes a row-major copy first. FastMicroGPT uses .reshape(...), which does the same thing: a view if possible, a copy if not. EX 6.3 shows the error you get if you forget.

F.scaled_dot_product_attention

Scores, mask, softmax and weighted sum are so common that PyTorch has one function for them. Check it against the manual version before trusting it:

from torch.testing import assert_close

def manual_attention(q, k, v):
    T, D = q.shape[-2], q.shape[-1]
    scores = q @ k.transpose(-2, -1) / math.sqrt(D)
    mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=q.device), diagonal=1)
    scores = scores.masked_fill(mask, float("-inf"))
    return F.softmax(scores, dim=-1) @ v

torch.manual_seed(0)
q, k, v = (torch.randn(2, 4, 5, 4) for _ in range(3))     # (B, H, T, D)

ref = manual_attention(q, k, v)
fast = F.scaled_dot_product_attention(q, k, v, is_causal=True)
assert_close(fast, ref)
print(fast.shape, torch.allclose(fast, ref, atol=1e-6), (fast - ref).abs().max().item())
torch.Size([2, 4, 5, 4]) True 2.384185791015625e-07

torch.testing.assert_close raises with a detailed report if the tensors differ beyond dtype-appropriate tolerances (for float32: rtol=1.3e-6, atol=1e-5); torch.allclose returns a bool. Prefer assert_close in tests. A difference of 2e-7 is float32 rounding from a different order of operations, not a bug.

Why use it: on a CUDA GPU, SDPA can dispatch to fused kernels (FlashAttention-2, memory-efficient attention) that compute attention in tiles and never write the full (B, H, T, T) score matrix to GPU memory. At T = 16 that doesn't matter; at T = 32,768 the score matrix alone would be gigabytes. Which kernel runs depends on the GPU, dtype and arguments, and those fused backends need a CUDA GPU. The context manager torch.nn.attention.sdpa_kernel(SDPBackend.MATH) (or FLASH_ATTENTION, EFFICIENT_ATTENTION, CUDNN_ATTENTION) restricts which backends may be used, which is how you check a result against the plain math version on a GPU.

is_causal=True with a KV cache

is_causal=True builds the mask as if query i and key i are the same position (top-left aligned). During generation with a KV cache you have 1 new query and many cached keys; with is_causal=True that one query may only see key 0. On a test with 6 cached keys, the "causal" output equalled v[0] exactly. For a single decoding step, leave is_causal off: the new token may see every cached key. Chapter 10 builds this properly.

MLP, residuals, and the modern variants

The rest of the block is your mlp and add_residual. As modules:

class MLP(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.up = nn.Linear(cfg.n_embd, cfg.mlp_hidden, bias=False)     # 16 -> 64
        self.down = nn.Linear(cfg.mlp_hidden, cfg.n_embd, bias=False)   # 64 -> 16

    def forward(self, x):
        return self.down(F.relu(self.up(x)))

# in Block.forward: pre-norm residual blocks, exactly microgpt's order
x = x + self.attn(self.norm1(x))
x = x + self.mlp(self.norm2(x))

The residual add means each sub-layer only learns a correction to x, and gradient flows straight through the + to earlier layers (the local gradient of addition is 1, as in your __add__). "Pre-norm" means the norm is applied to the sub-layer's input, not to the sum.

microgpt uses ReLU. GPT-2 used GELU (F.gelu), a smooth ReLU. Llama, Mistral and most current open models use SwiGLU: two up-projections, one passed through SiLU (x * sigmoid(x)) and multiplied elementwise with the other, then a down-projection. It has three weight matrices instead of two; EX 6.5 counts what that costs.

Assembling Block and GPT

Everything together, with microgpt's hyperparameters as defaults. bias=False everywhere and RMSNorm without a gain, so the parameter count matches.

pythongpt.py
import math
from dataclasses import dataclass

import torch
from torch import nn
import torch.nn.functional as F


@dataclass
class GPTConfig:
    vocab_size: int = 27      # a-z plus BOS
    block_size: int = 16      # maximum sequence length T
    n_embd: int = 16          # C
    n_head: int = 4           # H, so head_dim D = 16 // 4 = 4
    n_layer: int = 1          # microgpt has one block
    mlp_hidden: int = 64      # 4 * C
    final_norm: bool = False  # microgpt has none; GPT-2 and Llama do
    tie_weights: bool = False


class CausalSelfAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        assert cfg.n_embd % cfg.n_head == 0
        self.n_head = cfg.n_head
        self.head_dim = cfg.n_embd // cfg.n_head
        self.qkv = nn.Linear(cfg.n_embd, 3 * cfg.n_embd, bias=False)
        self.proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=False)
        mask = torch.triu(torch.ones(cfg.block_size, cfg.block_size, dtype=torch.bool), diagonal=1)
        self.register_buffer("causal_mask", mask, persistent=False)

    def forward(self, x):
        B, T, C = x.shape
        H, D = self.n_head, self.head_dim
        q, k, v = self.qkv(x).split(C, dim=-1)                  # 3 x (B, T, C)
        q = q.view(B, T, H, D).transpose(1, 2)                  # (B, H, T, D)
        k = k.view(B, T, H, D).transpose(1, 2)
        v = v.view(B, T, H, D).transpose(1, 2)
        scores = q @ k.transpose(-2, -1) / math.sqrt(D)         # (B, H, T, T)
        scores = scores.masked_fill(self.causal_mask[:T, :T], float("-inf"))
        weights = F.softmax(scores, dim=-1)
        out = weights @ v                                       # (B, H, T, D)
        out = out.transpose(1, 2).contiguous().view(B, T, C)    # merge heads
        return self.proj(out)


class MLP(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.up = nn.Linear(cfg.n_embd, cfg.mlp_hidden, bias=False)
        self.down = nn.Linear(cfg.mlp_hidden, cfg.n_embd, bias=False)

    def forward(self, x):
        return self.down(F.relu(self.up(x)))


class Block(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.norm1 = nn.RMSNorm(cfg.n_embd, eps=1e-5, elementwise_affine=False)
        self.attn = CausalSelfAttention(cfg)
        self.norm2 = nn.RMSNorm(cfg.n_embd, eps=1e-5, elementwise_affine=False)
        self.mlp = MLP(cfg)

    def forward(self, x):
        x = x + self.attn(self.norm1(x))     # residual add around attention
        x = x + self.mlp(self.norm2(x))      # residual add around the MLP
        return x


class GPT(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg = cfg
        self.tok_emb = nn.Embedding(cfg.vocab_size, cfg.n_embd)
        self.pos_emb = nn.Embedding(cfg.block_size, cfg.n_embd)
        self.blocks = nn.ModuleList([Block(cfg) for _ in range(cfg.n_layer)])
        if cfg.final_norm:
            self.norm_f = nn.RMSNorm(cfg.n_embd, eps=1e-5, elementwise_affine=False)
        else:
            self.norm_f = nn.Identity()
        self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        if cfg.tie_weights:
            self.lm_head.weight = self.tok_emb.weight   # one Parameter, two uses
        self.apply(self._init_weights)

    def _init_weights(self, module):
        if isinstance(module, (nn.Linear, nn.Embedding)):
            nn.init.normal_(module.weight, mean=0.0, std=0.08)   # microgpt's init

    def forward(self, idx):
        B, T = idx.shape
        assert T <= self.cfg.block_size, "sequence longer than block_size"
        pos = torch.arange(T, device=idx.device)
        x = self.tok_emb(idx) + self.pos_emb(pos)    # (B, T, C)
        for block in self.blocks:
            x = block(x)
        x = self.norm_f(x)
        return self.lm_head(x)                       # (B, T, vocab_size)

A few choices worth naming. The final norm (norm_f) normalises the last block's output before the LM head; GPT-2 and Llama have one, microgpt doesn't, so it's a flag and nn.Identity() (a module that returns its input) stands in when it's off. torch.arange(T, device=idx.device) creates positions on whatever device the input is on. The mask is a non-persistent buffer, as in FastMicroGPT.

weights = F.softmax(scores, dim=-1);              show("weights = softmax(masked)", weights)
out = weights @ v;                                show("out = weights @ v", out)
out = out.transpose(1, 2);                        show("out.transpose(1, 2)", out)
out = out.contiguous().view(B, T, C);             show(".contiguous().view(B, T, C)", out)
att = blk.attn.proj(out);                         show("attn.proj(out)", att)
x = x + att;                                      show("x = x + attn", x)
up = blk.mlp.up(blk.norm2(x));                    show("mlp.up(norm2(x))", up)
mlp = blk.mlp.down(F.relu(up));                   show("mlp.down(relu(.))", mlp)
x = x + mlp;                                      show("x = x + mlp", x)

Weight tying

The token embedding maps token id to vector, [V, C]. The LM head maps vector to a score per token, and its weight is also [V, C] (out = V, in = C). Weight tying uses one matrix for both. GPT-2 does it; it saves V × C parameters, which is a lot when V = 50,257. It's one assignment: make both modules hold the same Parameter object.

torch.manual_seed(0)

print(tied.lm_head.weight is tied.tok_emb.weight)
print(sum(p.numel() for p in tied.parameters()))          # shared tensor counted once
print([k for k in tied.state_dict() if "weight" in k and ("tok" in k or "lm" in k)])

3760
['tok_emb.weight', 'lm_head.weight']

parameters() skips duplicates, so the count drops by 432 to 3,760, and the optimizer updates the shared matrix once, with gradient from both uses summed (your += again). state_dict() still lists both names, pointing at the same tensor. Tie after creating both modules. If you initialise after tying, apply visits the shared tensor twice (as the embedding and as the head) and the last init wins; here both use the same normal init, so it doesn't matter, but with different schemes it would.

Fusing H and D into one dimension needs element (h, d+1) to sit right after (h, d), and (h+1, 0) right after (h, D-1). After the transpose, consecutive heads of one token are T · D elements apart, so no single stride describes the fused dim. view never copies, so it refuses; .contiguous().view and .reshape both copy into a fresh row-major buffer.

class SwiGLU(nn.Module):
    def __init__(self, n_embd, hidden):
        super().__init__()
        self.gate = nn.Linear(n_embd, hidden, bias=False)

EX 6.6 hard Multi-query attention

In multi-query attention (MQA) all H query heads share a single key head and a single value head. Write MultiQueryAttention with q: Linear(C, C) and kv: Linear(C, 2D), using broadcasting rather than copying K and V H times. Count its parameters against CausalSelfAttention, check it against F.scaled_dot_product_attention (with expand, and with enable_gqa=True), and say what it saves at inference time.

Show solution 
class MultiQueryAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n_head = cfg.n_head
        self.head_dim = cfg.n_embd // cfg.n_head
        self.q = nn.Linear(cfg.n_embd, cfg.n_embd, bias=False)          # H query heads
        self.kv = nn.Linear(cfg.n_embd, 2 * self.head_dim, bias=False)  # ONE key head, ONE value head
        self.proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=False)
        mask = torch.triu(torch.ones(cfg.block_size, cfg.block_size, dtype=torch.bool), diagonal=1)
        self.register_buffer("causal_mask", mask, persistent=False)

    def forward(self, x):
        B, T, C = x.shape
        H, D = self.n_head, self.head_dim
        q = self.q(x).view(B, T, H, D).transpose(1, 2)     # (B, H, T, D)
        k, v = self.kv(x).split(D, dim=-1)                  # (B, T, D) each
        k = k.unsqueeze(1)                                  # (B, 1, T, D): broadcasts over H
        v = v.unsqueeze(1)
        scores = q @ k.transpose(-2, -1) / math.sqrt(D)     # (B, H, T, T)
        scores = scores.masked_fill(self.causal_mask[:T, :T], float("-inf"))
        out = F.softmax(scores, dim=-1) @ v                 # (B, H, T, D)
        out = out.transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(out)

torch.manual_seed(0)
cfg = GPTConfig()
mqa = MultiQueryAttention(cfg)
x = torch.randn(2, 5, 16)
y = mqa(x)
print(y.shape, sum(p.numel() for p in mqa.parameters()))

H, D = cfg.n_head, C // cfg.n_head

k, v = mqa.kv(x).split(D, dim=-1)
k, v = k.unsqueeze(1), v.unsqueeze(1)                   # (B, 1, T, D)
ref1 = F.scaled_dot_product_attention(q, k.expand(B, H, T, D), v.expand(B, H, T, D), is_causal=True)
ref2 = F.scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True)

    assert_close(y, mqa.proj(out.transpose(1, 2).reshape(B, T, C)))

matches SDPA with expand() and with enable_gqa=True

640 parameters instead of 1,024 (q 256 + kv 128 + proj 256). The real win is at inference: the KV cache stores one key and one value vector of size D per token instead of H of them, so it is H times smaller (4× here, 32× or more in big models), and every decoding step reads H times less cache from memory. expand makes a broadcast view with stride 0 along H, so no copy happens either. Grouped-query attention (GQA, used by Llama 2 70B and Llama 3) sits in between: G key/value heads, each shared by H/G query heads; enable_gqa=True (PyTorch 2.5+) handles that case too.

Recap

  • Going from (T, C) to (B, T, C) only changes code that names dimensions by position; Linear, norms and softmax(dim=-1) are batch-agnostic, and @ batches over leading dims.
  • Heads: view(B, T, H, D).transpose(1, 2) to split, transpose(1, 2).contiguous().view(B, T, C) (or reshape) to merge.
  • Attention: q @ k.transpose(-2, -1) / sqrt(D), masked_fill(triu(diagonal=1), -inf), softmax(dim=-1), @ v. With all positions computed at once, the mask is what makes the model causal.
  • F.scaled_dot_product_attention(q, k, v, is_causal=True) matches the manual version and can use fused kernels on CUDA. Don't use is_causal=True for a single decode step against a KV cache.
  • nn.RMSNorm needs an explicit eps to match microgpt; elementwise_affine=False removes the gain.
  • A pre-norm block is x + attn(norm(x)) then x + mlp(norm(x)). ReLU in microgpt, GELU in GPT-2, SwiGLU in Llama.
  • The assembled GPT has 4,192 parameters, matches FastMicroGPT bit for bit, and drops to 3,760 with weight tying.
